## Связи

`GET /api/health` отвечает `Health("ok")` прямо из роута. Интерфейса нет. `RoutesTest.health` проверяет статус 200.

`GET /api/days/{date}` берёт параметр и вызывает `days.load`. `StoredDays.load` парсит дату и дважды вызывает `ActivityStore.find`: для `Log` и для `Schedule`. Беклог в ответ не входит. Плохая дата бросает `BadDate`, `Module.kt` отвечает 400 и `ErrorBody`. `DayRoutesTest.returnsLogAndScheduleForTheDay` идёт через `StoredDays` и H2: день с журналом и планом, пустой день, отсутствие беклога. `DayRoutesTest.rejectsBadDate` проверяет `2026-13-01` и текст «Неверная дата». До `find` этот запрос не доходит: дата отсекается в `parseDay`.

`POST /api/sessions` вызывает `sessions.open()`. `SessionBook.open` создаёт UUID и пустую историю. `RoutesTest.passesTextThrough` вызывает роут, но подставляет заглушку `Turns`, которая возвращает `"session-1"`. `SessionBook` этим тестом не исполняется.

`POST /api/sessions/{id}/messages` читает `IncomingMessage` и вызывает `sessions.message`. `SessionBook.message` при пустом тексте бросает `BlankMessage`, при чужом id — `SessionNotFound`, иначе `agent.handle`. `StatusPages` отвечает 400 «Пустое сообщение», 404 «Сессия не найдена», 502 при `ModelFailure`. `RoutesTest.passesTextThrough` проверяет только удачный ответ заглушки и что в неё ушли id и текст.

`staticResources("/", "web", index = "index.html")` отдаёт каталог `web`. `RoutesTest.chatPage` запрашивает `GET /` и ищет в теле «Рабочий помощник». `index.html` ссылается на `/chat.css` и `/chat.js`. Запросов к этим путям в тестах нет. `chat.js` сам вызывает `POST /api/sessions` и `POST /api/sessions/{id}/messages`.

`Application.workMcp` вызывает `mcpStatelessStreamableHttp(path = "/mcp")` на отдельном порту. Список HTTP-методов этого обработчика в репозитории не записан: его задаёт SDK. `McpToolsTest.journalGoesThroughMcp` поднимает этот сервер и ходит на `http://127.0.0.1:$port/mcp` через `StreamableHttpClientTransport`.

## Bug Fix, 15:46

Задача: журнал не принимает `HTTPS://example.com/doc`. Нижний регистр `http://` и `https://` уже работает. Пробелы по краям не должны ломать ссылку. Адрес без схемы по-прежнему отклоняется. Имя файла в задаче не было.

Журнал:

1. Прочитал правила, `ToolArgs.kt`, `WorkMcp.kt`, соседние тесты.
2. Запустил `McpToolsTest`, `DayRoutesTest`, `ActivityStoreTest`.
3. Написал `ToolArgsTest` и запустил его. До правки `linkKeepsUppercaseHttpsAndTrimmedEdges` упал с `ToolInputError`.
4. Поправил `link()`: `trim()` и `ignoreCase = true`.
5. Повторил `ToolArgsTest` вместе с `McpToolsTest`, `DayRoutesTest`, `ActivityStoreTest`, `SourceRulesTest`, `RoutesTest` и прочитал `TEST-app.work.server.tool.ToolArgsTest.xml`.

Код, который остался:

```kotlin
fun JsonObject.link(): String? {
    val value = optionalText("link")?.trim() ?: return null
    if (value.length > 2_000) throw ToolInputError("Слишком длинная ссылка")
    if (!value.startsWith("https://", ignoreCase = true) && !value.startsWith("http://", ignoreCase = true)) {
        throw ToolInputError("Ссылка должна начинаться с http:// или https://")
    }
    return value
}
```

Ответ:

**Что нашёл.** Журнал пишет ссылку через `JsonObject.link()`. Схема проверялась как `https://` и `http://` в нижнем регистре, пробелы по краям не снимались. Из-за этого `HTTPS://example.com/doc` отклонялась с ошибкой «Ссылка должна начинаться с http:// или https://». Старые тесты этого не ловили: они передают только `https://` без пробелов и проходили.

**Что починил.** В `link()` ссылка сначала обрезается по краям, затем схема `http`/`https` принимается в любом регистре. В журнал сохраняется уже обрезанная ссылка, например `HTTPS://example.com/doc`. Адрес без схемы по-прежнему отклоняется с той же ошибкой.

**Что проверил.** До правки `ToolArgsTest.linkKeepsUppercaseHttpsAndTrimmedEdges` падал с `ToolInputError`. После правки прошли `ToolArgsTest` (верхний регистр, пробелы по краям, `http://` и `https://`, отказ адреса без схемы), а также соседние `McpToolsTest`, `DayRoutesTest`, `ActivityStoreTest`, `RoutesTest` и `SourceRulesTest`.
