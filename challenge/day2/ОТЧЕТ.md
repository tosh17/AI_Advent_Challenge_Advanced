# День 2. Profiles

Ветка `day2`, коммит `4f5168f`. Код задания — три профиля и два изменения, которые профили сделали сами. Этот файл — отчёт для сдачи и текст, по которому снимается видео.

## Что требовалось

Два профиля агентного режима и проверка каждого на живой задаче с первого запуска.

Bug Fix получает баг, сам находит причину, чинит и проверяет, что соседнее поведение живо. Research получает вопрос по кодовой базе, сам читает проект и отвечает структурой, код не меняет. У каждого профиля четыре части: инструкция, что делать, чего не делать, формат ответа.

Если первый запуск не дал рабочего результата, профиль дорабатывается и задача запускается снова. В отчёте нужно написать, что именно пришлось поменять.

Третий профиль — под частую задачу этого репозитория. Тот же принцип: один запуск, рабочий результат.

Сдача: видео и код. В видео должны быть видны профили, первый запуск и итог. В коде — файлы профилей и правки, которые сделали Bug Fix и Endpoint.

## Что лежит в коде

Профили — файлы Cursor, их подхватывает агентный режим:

- `.cursor/agents/bug-fix.md`
- `.cursor/agents/research.md`
- `.cursor/agents/endpoint-author.md`

Третий профиль назван Endpoint. Частая задача проекта — новый HTTP endpoint: тонкий роут, один метод узкого интерфейса, тест на H2. Профиль под эту задачу уже был, на дне 2 его инструкция переписана под текущую архитектуру: локальные активности, без вызова Jira и Confluence из роута, спринт в ответ дня не попадает.

Профили написаны до запусков. После трёх запусков текст профилей не менялся.

## Три запуска

### Research

Вопрос: какие HTTP-эндпоинты есть и какие из них не покрыты тестами.

Ответ пришёл в трёх блоках: файлы, связи, выводы. В конце — список эндпоинтов и файл теста либо пометка, что теста нет. Файлы репозитория этот запуск не изменил.

Он прошёл по цепочке роут → интерфейс → реализация → тест и назвал:

- `GET /api/days/{date}` — `DayRoutesTest`, включая плохую дату

- `GET /` — `RoutesTest.chatPage`

Дыры, которые он назвал: `GET /chat.js`, `GET /chat.css`, ветки `400` / `404` / `502` у сообщения. Эти дыры закрыты уже на дне 3, в день 2 их только нашли.

### Bug Fix

Симптом: инструмент журнала не принимает `HTTPS://example.com/doc`, хотя это та же https-ссылка. Ссылки `http://` и `https://` в нижнем регистре уже работают. Пробелы по краям не должны ломать ссылку. Адрес без схемы по-прежнему отклоняется.

Профиль сам открыл правила, `ToolArgs.kt`, регистрацию инструмента в `WorkMcp.kt` и соседние тесты. Причина нашлась в `JsonObject.link()`: схема сравнивалась как `https://` и `http://` только в нижнем регистре, края строки не обрезались.

Починка: ссылка обрезается, схема принимается в любом регистре, в журнал пишется уже обрезанное значение. Адрес без схемы по-прежнему получает «Ссылка должна начинаться с http:// или https://».

Проверки на этот случай не было. Профиль добавил `ToolArgsTest`. До правки новый тест падал с `ToolInputError`. После правки прошли `ToolArgsTest`, `McpToolsTest`, `DayRoutesTest`, `ActivityStoreTest`, `RoutesTest` и `SourceRulesTest`.

Ответ пришёл тремя блоками: что нашёл, что починил, что проверил.

### Endpoint

Задача: `GET /api/sprint`. В ответе только уже записанные активности вида Sprint. Журнал, план и беклог в список не входят.

Профиль добавил интерфейс `Sprint` и `StoredSprint`. Роут вызывает `sprint.load()` и не трогает `ActivityStore`. DTO `SprintResponse` лежит в `Routes.kt`. Тест `SprintRoutesTest` открывает базу через `connect()`, кладёт спринт и запись журнала и проверяет, что в ответе только спринт.

Прошли `SprintRoutesTest`, `RoutesTest`, `DayRoutesTest` и полный `./gradlew :server:test`.

Ответ: какой путь добавлен, какие файлы изменены, какой командой проверено.
