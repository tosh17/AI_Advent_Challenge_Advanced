# День 15. Заказы

Сервис для пяти покупателей. У каждого своя история заказов за сентябрь и октябрь. Модель `deepseek-v4-flash` на `https://api.deepseek.com` помогает найти заказ, записать новый и сказать, что пора купить. Это тот же API, что у сервиса ops: обычный DeepSeek, без дообучения. Ключ читается из окружения `DEEPSEEK_API_KEY` и в репозиторий не входит. Подсказка считается в базе: товар брали хотя бы дважды, и с последней покупки прошло 14 или больше дней.

Снаружи сервис открыт по адресу http://194.32.243.134:8815/

База SQLite, файл `data/shop.db`, создаётся при первом запуске. Все вызовы модели идут через шлюз дня 13 в режиме `mask`, а шлюз отправляет уже замаскированный текст в DeepSeek.

## Свой фронт

Страница `GET /` и `GET /index.html` — наш клиент, файл `index.html`. Это чат на весь экран. После входа видна переписка, поле сообщения и три быстрые кнопки. Покупка — обычное сообщение, например «запиши молоко, 2 штуки». Отчёт тоже сообщение: модель отвечает в ленте, отдельных списков на странице нет.

Кнопки не вызывают другие ручки. Каждая отправляет текст в `POST /api/chat`:

- «Что пора купить?»
- «Покажи мои заказы»
- «Что я покупал чаще всего?»

Токен и имя лежат в `sessionStorage`. Выход их стирает и возвращает форму входа.

Ручки ниже — для человека, который пишет свой фронт. Наш клиент ими заказы не рисует.

## Вход

`POST /api/login` без токена.

```json
{"login":"marina","password":"marina"}
```

Ответ `200`:

```json
{"token":"...","name":"Марина","login":"marina"}
```

Дальше на каждый запрос заголовок `Authorization: Bearer <token>` и `Content-Type: application/json`, если есть тело. Токен не сгорает сам, пока жива база.

`401` и `{"error":"Неверный логин или пароль."}`, если пара не подошла. `401` и `{"error":"Нужен вход."}`, если токена нет или он чужой. `400` и `{"error":"Тело не JSON."}`, если тело не объект JSON.

## Ручки для своего фронта

### Заказы

`GET /api/orders`

```json
{
  "name": "Марина",
  "orders": [
    {"id": 1, "item": "молоко", "qty": 1, "note": "", "bought_on": "2026-09-01"}
  ]
}
```

`POST /api/orders` пишет сразу, модель не вызывается.

```json
{"item":"сахар","qty":2,"note":""}
```

`note` можно не присылать, тогда заметка пустая. Ответ `200` — записанный заказ с теми же полями `id`, `item`, `qty`, `note`, `bought_on`. Дата ставится сегодняшняя. `400` и `{"error":"Нужны товар и количество."}`, если товар пустой или количество меньше 1. `400` и `{"error":"Количество не число."}`, если количество не целое.

`GET /api/orders/search?q=молоко` ищет подстроку в товаре и в заметке только этого покупателя.

```json
{"orders": [{"id": 1, "item": "молоко", "qty": 1, "note": "", "bought_on": "2026-09-01"}]}
```

Пустой `q` даёт `400` и `{"error":"Пустой поиск."}`.

### Подсказка

`GET /api/hints`

```json
{"hints": [{"item": "молоко", "last_on": "2026-10-27", "times": 9}]}
```

В список попадает товар, который встречался хотя бы два раза, и последняя дата старше или равна 14 дням.

### Чат

`POST /api/chat`

```json
{"text":"что пора купить?"}
```

Пустой текст даёт `400` и `{"error":"Пустое сообщение."}`.

Ответ `200`:

```json
{
  "reply": "Пора купить молоко, последний раз 2026-10-27.",
  "stopped": false,
  "committed": false,
  "warning": "",
  "tool": ""
}
```

- `reply` — текст человеку
- `stopped` — шлюз или проверка не пропустили шаг
- `committed` — заказ из чата записан в базу
- `warning` — текст замечания уровня Medium, если оно было
- `tool` — имя инструмента, если модель его вызвала: `orders_list`, `orders_search`, `orders_add`, `buy_hints`

Секрет во истории или в сообщении магазин не останавливает: шлюз в режиме `mask` ставит метку и вызывает модель. `sent` при этом `true`. Остановка `sent: false` и текст «Запрос остановлен: во входящем тексте секрет. В модель ничего не ушло.» остаются у отдельного шлюза в режиме `block`.

Модель видит историю этого человека, подсказки и прайс из `catalog/supplier.txt`. Файл читается на каждый чат. Инструмент выбирает модель и присылает один JSON:

```json
{"tool":"orders_add","item":"молоко","qty":1}
{"tool":"orders_search","query":"молоко"}
{"tool":"orders_list"}
{"tool":"buy_hints"}
```

Запись из чата сохраняется, когда человек просит записать покупку и товар назван в его сообщении, а вторая проверка ответила `CLEAN` или `Medium`. Вопрос вроде «пылесос я не покупал?» заказ не создаёт. При `Medium` в `warning` лежит причина, `committed` при этом `true`. `High`, неясный ответ проверки и остановка шлюза заказ не пишут, `committed` остаётся `false`.

### MCP

`POST /mcp` — те же четыре инструмента для чужого клиента, без модели и без второй проверки. `orders_add` здесь пишет сразу.

```json
{"name":"orders_list","arguments":{}}
{"name":"orders_search","arguments":{"query":"молоко"}}
{"name":"orders_add","arguments":{"item":"сахар","qty":2}}
{"name":"buy_hints","arguments":{}}
```

Ответ `200`:

```json
{"tool":"orders_list","result":[{"id":1,"item":"молоко","qty":1,"note":"","bought_on":"2026-09-01"}]}
```

У `orders_add` в `result` один заказ. У `buy_hints` массив таких же объектов, как у `GET /api/hints`. Неизвестное имя даёт `400` и `{"error":"Нужно имя инструмента."}`. Пустые товар или количество у `orders_add` дают `400` и `{"error":"Нужны товар и количество."}`.

## Ошибки

| Код | Когда |
|---|---|
| 200 | Запрос выполнен |
| 400 | Пустое сообщение, пустой поиск, плохое количество, не JSON, неизвестный инструмент |
| 401 | Нет входа или пароль не подошёл |
| 404 | `{"error":"Нет такого пути."}` |
| 500 | Сбой сервера, в `error` имя исключения |

## Шлюз

В процессе магазина работает тот же `Gateway` дня 13, режим `mask`, лимит 60 запросов в минуту с одного адреса. Дальше запрос уходит в `POST https://api.deepseek.com/chat/completions`, модель `deepseek-v4-flash`. Отдельно шлюз поднимается из `challenge/day13`:

```bash
python3 gateway.py
```

Он слушает `http://127.0.0.1:8793`. Вызов: `POST /v1/chat/completions`. Заголовок `X-Guard-Mode` равен `block` или `mask`. Без заголовка режим `block`.

Тело:

```json
{"model":"qwen2.5:3b","messages":[{"role":"user","content":"текст"}]}
```

- `200` — ответ модели в `choices[0].message.content`, служебные поля в `gateway`
- `400` — во входе секрет, в модель ничего не ушло
- `422` — ответ модели скрыт: системный промпт или опасная команда
- `429` — лимит, у отдельного шлюза он 10 в минуту

`GET /health` магазина отвечает `{"status":"ok"}`.
